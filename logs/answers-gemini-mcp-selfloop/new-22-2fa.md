# How does two-factor authentication (2FA) work in Rocket.Chat?

## Plan

intent: architecture

## Gemini Answer

Two-factor authentication (2FA) in Rocket.Chat is implemented through a middleware wrapper called `twoFactorRequired` located in `apps/meteor/app/2fa/server/twoFactorRequired.ts`. This wrapper is applied to sensitive methods and endpoints to enforce 2FA.

When 2FA is triggered, the system calls `checkCodeForUser` (defined in `apps/meteor/app/2fa/server/code/index.ts`). This function attempts to verify the user's identity using a series of methods, prioritizing them in the following order:

1.  **TOTPCheck (Authenticator App):** This method uses standard RFC 6238 time-based one-time passwords, typically generated by an authenticator app.
2.  **EmailCheck (Email Code):** If TOTP is not used or fails, a temporary code is sent to the user's email address via the Mailer.
3.  **PasswordCheckFallback:** As a last resort, a password check can be used as a fallback mechanism.

Each of these verification methods (TOTPCheck, EmailCheck, PasswordCheckFallback) implements the `ICodeCheck` interface (defined in `apps/meteor/app/2fa/server/code/ICodeCheck.ts`), which includes `verify()` and `isEnabled()` methods.

The `checkCodeForUser` function first checks if 2FA is enabled globally. It then retrieves the user and, if a code and method are not explicitly provided, attempts to extract them from `x-2fa-code` and `x-2fa-method` HTTP headers.

The `getSecondFactorMethod` function (also in `apps/meteor/app/2fa/server/code/index.ts`) is responsible for selecting the appropriate 2FA method. It tries to find an active method for the user or uses the method provided. If no method is found but 2FA is required, it defaults to the `passwordCheckFallback`.

If a code is provided, `checkCodeForUser` calls the `verify()` method of the selected 2FA method. If the verification fails, it checks for too many failed attempts and throws an error accordingly. If successful, and "remember me" is not disabled, the authorization is remembered for the connection.

The client-side component `TwoFactorRequiredModal.tsx` (located in `apps/meteor/client/views/root/MainLayout/TwoFactorRequiredModal.tsx`) is responsible for displaying the 2FA modal to the user.
