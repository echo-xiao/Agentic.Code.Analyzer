# How are the keys managed for end-to-end (E2E) encryption in Rocket.Chat?

## Gemini Answer

Rocket.Chat manages E2E encryption keys primarily on the client-side, within `apps/meteor/client/lib/e2ee/`.

The key management process involves:

1.  **RSA Key Pair Generation:** The `createAndLoadKeys()` function, located in `apps/meteor/client/lib/e2ee/rocketchat.e2e.ts`, is responsible for generating an RSA key pair. This generation is facilitated by `generateKeyPair()` in `apps/meteor/client/lib/e2ee/crypto/shared.ts`.
2.  **Private Key Encryption:** The generated RSA private key is then encrypted. This encryption uses a derived key from PBKDF2 (Password-Based Key Derivation Function 2) and subsequently employs AES-GCM (Advanced Encryption Standard - Galois/Counter Mode) for the actual encryption.
3.  **Per-Room Session Keys:** For each E2E encrypted room, an AES session key is generated by `E2ERoom.createGroupKey()` in `apps/meteor/client/lib/e2ee/rocketchat.e2e.room.ts`. This session key is then encrypted for each participant in the room using their respective RSA public keys via `encryptGroupKeyForParticipant()`.
4.  **Key Storage:** An internal Keychain component, utilizing `EncryptedKeyCodec`, manages the storage of these encrypted keys.
5.  **Cryptographic Primitives:** The core cryptographic operations (RSA, AES, PBKDF2) are implemented in `apps/meteor/client/lib/e2ee/crypto/rsa.ts`, `apps/meteor/client/lib/e2ee/crypto/aes.ts`, and `apps/meteor/client/lib/e2ee/crypto/pbkdf2.ts`.
6.  **Server-Side Settings:** The server enforces E2E related settings like `E2E_Enable` and `E2E_Allow_Unencrypted_Messages`.

The call chain for generating the initial RSA key pair is:
`createAndLoadKeys` (apps/meteor/client/lib/e2ee/rocketchat.e2e.ts) → `generate` (apps/meteor/client/lib/e2ee/helpers.ts) → `generateKeyPair` (apps/meteor/client/lib/e2ee/crypto/shared.ts).
