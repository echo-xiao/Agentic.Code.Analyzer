# How does enterprise feature gating work in Rocket.Chat?

intent: unknown

## Gemini Answer

Rocket.Chat's enterprise feature gating is managed by the **LicenseManager** system, which is responsible for validating licenses, enabling/disabling features, and enforcing usage limits.

Here's a breakdown of how it works:

**Core Component:**

*   **`LicenseManager`** (`ee/packages/license/src/license.ts`): This abstract class extends an `Emitter` to broadcast license-related events. It handles the entire lifecycle of a license, including:
    *   Decryption and validation of the license.
    *   Tracking of feature modules.
    *   Enforcement of usage limits.
    *   Providing methods like `hasModule()` to check for specific enterprise features and `isLimitReached()` to verify usage against license limits.

**Integration and Usage:**

The `LicenseManager` is widely used across the Rocket.Chat codebase to gate enterprise features. For example:

*   **Omnichannel Features:**
    *   `LivechatEnterprise` (`apps/meteor/ee/app/livechat-enterprise/server/lib/LivechatEnterprise.ts`) provides methods for managing enterprise-specific livechat features like monitors, business units, tags, and SLAs. These operations are implicitly or explicitly tied to the active license.
    *   `isDepartmentCreationAvailablePatch` (`ee/packages/omni-core-ee/src/isDepartmentCreationAvailable.ts`) overrides the default department creation logic to allow unlimited departments when a `livechat-enterprise` module is active in the license.
*   **Apps and Integrations:**
    *   `_canEnableApp` (`apps/meteor/ee/app/license/server/canEnableApp.ts`) validates whether an app can be enabled based on the current license and app storage constraints.
    *   Enterprise cron jobs, such as `Apps-Engine:check` and `Apps-Request-End-Users:notify` (`apps/meteor/ee/server/apps/cron.ts` and `apps/meteor/ee/server/apps/appRequestsCron.ts` respectively), rely on `getWorkspaceAccessToken` for authentication and `Apps.getMarketplaceClient()` for external communication, which are likely gated by the license.
*   **API and Security:**
    *   `isLicenseEnabledMiddleware` (`ee/packages/federation-matrix/src/api/middlewares/isLicenseEnabled.ts`) enforces license requirements for certain API endpoints, particularly for federation features.
    *   `api.ts` (`apps/meteor/ee/server/api/api.ts`) includes enterprise API middleware that enforces two-factor authentication when no valid license is present.

**Flow of Enterprise Feature Gating:**

1.  **License Acquisition/Setting:** An encrypted license is set in the system via `LicenseManager.setLicense()`.
2.  **License Validation:** The `LicenseManager` decrypts and validates the license, checking its format, modules, and usage limits.
3.  **Feature Access Check:** When an enterprise feature is requested or accessed, the system calls methods on the `LicenseManager` (e.g., `hasModule()`, `isLimitReached()`) to determine if the current license permits the operation.
4.  **Behavior Enforcement:** Based on the license validation, the system either allows the feature, prevents the action, or triggers specific behaviors (e.g., notifications, warnings). This can involve patching core functionalities or applying middleware.

In essence, the `LicenseManager` acts as the central gatekeeper, ensuring that enterprise functionalities are only available to Rocket.Chat instances with valid and appropriate licenses.
