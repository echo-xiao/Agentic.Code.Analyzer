# How does two-factor authentication (2FA) work in Rocket.Chat?

## Baseline Answer (no tools)

Rocket.Chat implements two-factor authentication (2FA) to add an extra layer of security to user accounts. It supports several methods, primarily Time-based One-Time Passwords (TOTP) and WebAuthn (FIDO2), with email-based 2FA also available in some contexts.

Here's a breakdown of how 2FA works in Rocket.Chat:

### 1. Supported 2FA Methods

*   **TOTP (Time-based One-Time Password)**: This is the most common method, where users use an authenticator app (like Google Authenticator, Authy, Microsoft Authenticator) to generate a six-digit code that changes every 30-60 seconds.
*   **WebAuthn (FIDO2)**: A newer, more secure standard that uses hardware security keys (e.g., YubiKey, Ledger) or built-in platform authenticators (e.g., Windows Hello, Touch ID) for authentication.
*   **Email 2FA**: While not a primary user-configurable 2FA method for general logins, email verification is used in specific flows like password resets or when an administrator forces email verification for new accounts.

### 2. Enrollment Process (Example: TOTP)

1.  **User Initiates Setup**: A user navigates to their account security settings in Rocket.Chat.
2.  **Server Generates Secret**: The client requests a new 2FA secret from the server. The server generates a unique, cryptographically secure secret key for the user.
    *   **Server-side**: This is handled by a method like `generateTwoFactorSecret` which uses the `speakeasy` library.
        *   `app/2fa/server/methods/generateTwoFactorSecret.ts`
        *   `app/2fa/server/lib/totp.ts` (contains `generateSecret` function)
3.  **Display QR Code/Key**: The server sends the secret back to the client. The client then displays a QR code (generated from the secret and user details) and a manual key for the user to add to their authenticator app.
    *   **Client-side**: `client/views/account/security/TwoFactorTOTP.tsx` handles the UI for this.
4.  **User Configures Authenticator App**: The user scans the QR code or manually enters the key into their chosen authenticator app.
5.  **Verification**: The user enters a code generated by their authenticator app into Rocket.Chat to verify the setup.
    *   **Client-side**: The code is sent to the server via a method call.
    *   **Server-side**: The `enableTwoFactor` method receives the code and verifies it against the generated secret.
        *   `app/2fa/server/methods/enableTwoFactor.ts`
        *   `app/2fa/server/lib/totp.ts` (contains `verify` function)
6.  **Server Stores Secret**: If the verification is successful, the server stores the *hashed* or *encrypted* 2FA secret in the user's document in the `users` collection. It also generates and stores a set of recovery codes.
    *   **Database**: The `users` collection (managed by `app/models/server/raw/Users.ts`) stores the `twoFactor` field, which contains `enabled`, `secret`, `codes`, and `webauthn` details.

### 3. Login Process (Example: TOTP)

1.  **Username/Password Entry**: The user enters their username and password as usual.
2.  **Server Verifies Credentials**: Rocket.Chat's authentication system verifies the username and password.
3.  **2FA Check**: After successful password verification, the server checks if 2FA is enabled for that user.
    *   **Server-side**: This check is typically integrated into the `Accounts.validateLoginAttempt` hook or a custom login handler.
        *   `app/2fa/server/lib/twoFactorRequired.ts` is a key utility function to determine if 2FA is required for a given login attempt.
4.  **Prompt for 2FA Code**: If 2FA is enabled, the server sends a signal to the client, indicating that a 2FA code is required. The client then displays a modal for the user to enter their 2FA code.
    *   **Client-side**: `client/views/login/TwoFactorTOTPModal.tsx` is used for this.
5.  **User Enters 2FA Code**: The user retrieves a code from their authenticator app and enters it into the Rocket.Chat login screen.
6.  **Server Verifies 2FA Code**: The client sends the 2FA code to the server. The server uses the stored (hashed/encrypted) secret to verify the provided code.
    *   **Server-side**: The `verifyCode` method is called.
        *   `app/2fa/server/methods/verifyCode.ts`
        *   `app/2fa/server/lib/totp.ts` (contains `verify` function)
7.  **Login Success/Failure**:
    *   If the 2FA code is valid, the login attempt is successful, and the user is granted access.
    *   If the code is invalid, the login fails.

### 4. WebAuthn (FIDO2) Specifics

*   **Enrollment**: Similar flow, but instead of a QR code, the user interacts with their security key or platform authenticator (e.g., fingerprint scan). The server stores the public key credential.
    *   **Server-side**: `app/webauthn/server/methods/` contains methods like `webauthnRegisterBegin` and `webauthnRegisterFinish`.
    *   **Client-side**: `client/views/account/security/WebAuthn.tsx`
*   **Login**: During login, after username/password, the server challenges the client to authenticate with their registered WebAuthn credential. The user interacts with their security key/authenticator, and the signed challenge is sent back to the server for verification.
    *   **Server-side**: `app/webauthn/server/methods/` contains methods like `webauthnLoginBegin` and `webauthnLoginFinish`.
    *   **Client-side**: `client/views/login/WebAuthnLoginModal.tsx`

### Key Code Paths and Components

*   **Server-side 2FA Logic**:
    *   `app/2fa/server/`: Contains the core server-side logic for TOTP 2FA.
        *   `app/2fa/server/startup.ts`: Initializes 2FA methods.
        *   `app/2fa/server/methods/`: Defines the Meteor methods for 2FA operations (enable, disable, generate secret, verify code).
        *   `app/2fa/server/lib/totp.ts`: Utility functions for TOTP secret generation and code verification using the `speakeasy` library.
        *   `app/2fa/server/lib/twoFactorRequired.ts`: Determines if a user needs to provide a 2FA code during login.
    *   `app/webauthn/server/`: Contains the server-side logic for WebAuthn (FIDO2).
        *   `app/webauthn/server/methods/`: Meteor methods for WebAuthn registration and authentication.
    *   `app/authentication/server/startup.ts`: Hooks into Meteor's `Accounts` system to integrate 2FA into the login flow.
    *   `app/models/server/raw/Users.ts`: The `Users` collection model, where 2FA secrets, recovery codes, and WebAuthn credentials are stored in the `twoFactor` field of a user document.

*   **Client-side 2FA UI**:
    *   `client/views/account/security/TwoFactorTOTP.tsx`: User interface for enabling and managing TOTP 2FA in account settings.
    *   `client/views/login/TwoFactorTOTPModal.tsx`: The modal displayed during login to prompt for a TOTP code.
    *   `client/views/account/security/WebAuthn.tsx`: User interface for enabling and managing WebAuthn.
    *   `client/views/login/WebAuthnLoginModal.tsx`: The modal displayed during login to prompt for WebAuthn authentication.

By combining server-side logic for secret management and code verification with client-side UI for user interaction, Rocket.Chat provides a robust 2FA system.
